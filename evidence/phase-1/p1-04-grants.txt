$ mysql -u root
  CREATE DATABASE p1_04_scratch ...;
  CREATE TABLE t (Sku VARCHAR(8), Qty DECIMAL(19,3)) ENGINE=InnoDB ...;

  -- Non-strict (P0-07): silently stored 'THIS-SKU' / 2.000, reported success.
  -- Strict (now):        rejected outright. The string-truncation half of ADR-003.2 is fixed.
  -- The decimal-SCALE half (1.9999 -> 2.000 rounding) is NOT fixed by strict mode — this is
  --    documented, expected, upstream behaviour (MySQL bug #87678, open). ADR-004.1 assigns
  --    that half to the API (Decimal.Round to storage scale before the parameter is bound),
  --    not the database. Not retested here because the insert never got that far (it failed
  --    on the Sku column first); P1-07/P1-11's own precision tests cover it directly.

=== Accounts created ===

merch_api  — DML + limited DDL (CREATE, ALTER, INDEX, REFERENCES). Deliberately NO DROP:
  DROP is a database-scoped privilege in MariaDB, so granting it on merchandising.* would
  also authorize DROP DATABASE merchandising — the opposite of what this card requires.
  Migrations are forward-only (ADR-008), so DROP was never needed for that either.
  No admin privileges (GRANT OPTION, SUPER, FILE, PROCESS, RELOAD, SHUTDOWN, CREATE USER).

merch_backup — exactly SELECT, LOCK TABLES, SHOW VIEW, EVENT, TRIGGER, per the card and
  plan.md, verbatim. Nothing else.

Both accounts scoped @'localhost' only, matching the loopback bind-address already set at
P0-04. MariaDB documents 'localhost' as covering TCP-loopback connections on Windows (no
Unix socket on this platform), which is how MySqlConnector will connect at P1-05.

$ mysql -u root -e "SHOW GRANTS FOR 'merch_api'@'localhost';"

=== Root account — no application uses it ===

root exists only with loopback-restricted hosts: localhost, 127.0.0.1, ::1. No 'root'@'%'
entry exists. This is a second, independent barrier on top of bind-address=127.0.0.1
(P0-04) — even if bind-address were ever loosened, root's own host grants would still
refuse a remote connection. No application account (merch_api, merch_backup) uses root;
neither was created with root-equivalent privileges.
