A REAL DEFECT FOUND WHILE WRITING THIS SUITE, before PART B was ever run:
MySqlConnector returns a CHAR(36) column (StockMovements.CorrelationId,
AuditLogs.CorrelationId) back as a System.Guid object, not a String.
`CStr(scalarResult)` on a Guid throws InvalidCastException - VB's CStr does
not support that conversion. Fixed in the test by calling `.ToString()` on
the scalar result instead (Guid.ToString()'s default "D" format is the same
lowercase-with-hyphens shape Guid.NewGuid().ToString() produces, which is
what was stored, so the round trip is exact either way). This is a read-back
detail specific to how the test verifies the database's own content - it
does not affect anything written by StockRepository/StockMovementWriter/
AuditLogWriter, which only ever bind String parameters on the way in.
