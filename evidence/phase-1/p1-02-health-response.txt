1  THE ENTRY POINT AS AUTHORED - Program.vb
---------------------------------------------------------------------------

  Public Module Program

      Public Sub Main(args As String())

          Dim builder = WebApplication.CreateBuilder(args)

          builder.Services.AddControllers()

          Dim app = builder.Build()

          app.MapControllers()

          app.Run()

      End Sub

  End Module

  MODULE PROGRAM / SUB MAIN, NOT TOP LEVEL STATEMENTS. Top level
  statements are a C# language feature and do not exist in Visual Basic;
  `Dim builder = WebApplication.CreateBuilder(args)` written at file scope
  is the single most likely way to drift into C#-shaped code in this
  project (CLAUDE.md section 3). It is written here as an ordinary Sub
  body inside a Module, which is the whole point of the rung A question.

  Public, not Friend, deliberately: P1-19 wires WebApplicationFactory,
  which needs the entry point reachable from the integration test
  assembly. The InternalsVisibleTo half of that seam is P1-19's work and
  is NOT done here.

  Sub, not Async Function ... As Task: app.Run() is the blocking overload,
  so there is nothing to await.

2  THE CONTROLLER AS AUTHORED - Controllers/HealthController.vb
---------------------------------------------------------------------------

  <ApiController>
  <Route("health")>
  Public Class HealthController
      Inherits ControllerBase

      Private Shared ReadOnly ProductVersion As String = ResolveProductVersion()

      <HttpGet>
      Public Function GetHealth() As IActionResult

          Dim payload = New With {
              .status = "ok",
              .version = ProductVersion,
              .utcTime = DateTime.UtcNow.ToString("o", CultureInfo.InvariantCulture)
          }

          Return Ok(payload)

      End Function

      ' ResolveProductVersion() reads AssemblyInformationalVersionAttribute
      ' and truncates at '+'. See section 5.

  End Class

  ATTRIBUTES USE ANGLE BRACKETS, each on its own line above the member, per
  CLAUDE.md section 3. Controller-based, not a minimal-API lambda.

  ROUTED AT /health, NOT /api/v1/health. Spec section 13 versions the API
  under /api/v1 but lists GET /health in the Operations row outside that
  prefix, as the one endpoint that does not require authentication. The
  route follows the spec, not the general rule.

5  THE THREE FIELDS, AND WHERE version COMES FROM
---------------------------------------------------------------------------

  Parsed from the response body:

    status     = ok
    version    = 0.1.0
    utcTime    = 2026-08-16T09:37:27.8769798Z
    field count: 3

  EXACTLY THREE FIELDS. The card specifies {status, version, utcTime} and
  the response carries those three and nothing else.

  (When the body is piped through PowerShell's ConvertFrom-Json the
  utcTime value is displayed as a coerced local DateTime, "8/16/2026
  9:37:27 AM". That is a display artefact of the parser, not the wire
  format. The raw body above is the wire format: ISO 8601, round-trip
  format specifier "o", CultureInfo.InvariantCulture, trailing Z.)

  version IS READ FROM THE ASSEMBLY, NOT HARD CODED. Directory.Build.props
  owns <Version>0.1.0</Version>; a literal in the controller would drift
  from it silently. HealthController.ResolveProductVersion() reads
  AssemblyInformationalVersionAttribute once at type initialisation and
  TRUNCATES ANYTHING FROM '+' ONWARDS.

  That truncation is a deliberate safeguard, not tidying. The .NET SDK
  appends a source revision identifier after '+' when one is available
  (SourceLink, or an explicitly set SourceRevisionId). None is configured
  today, so the value is a clean "0.1.0" - but adding SourceLink later is
  an ordinary thing to do, and it would otherwise start publishing a
  commit hash from an unauthenticated endpoint that anyone who can reach
  the port may read. The strip means that cannot happen by accident.

6  WHAT THE RESPONSE WITHHOLDS  - the Done-when box that matters most
---------------------------------------------------------------------------

  "Health response contains no secrets, DB status detail, or environment
  strings." For an endpoint that is unauthenticated by design, what it
  omits is more important than what it returns.

  BODY: three fields, listed above. No database status, reachability, or
  connection detail; no configuration values; no hosting environment name;
  no machine, user or account name; no file path; no exception, message or
  stack trace. There is no code path in HealthController that can emit any
  of them - it has no dependencies injected at all, so it has nothing to
  report about.

  ALL RESPONSE HEADERS, verbatim - checked because a header leaks just as
  effectively as a body field:

    Date: Sun, 16 Aug 2026 09:37:27 GMT
    Server: Kestrel
    Transfer-Encoding: chunked
    Content-Type: application/json; charset=utf-8

  Four headers, all protocol-level. "Server: Kestrel" names the web server
  and nothing more - no version, no OS, no framework build. No
  X-Powered-By, no ASP.NET version header, no correlation of any kind yet
  (the correlation ID design is P1-08 onwards).

  NOTE THE ASYMMETRY WITH THE SERVER LOG. The startup log in section 3
  prints "Hosting environment: Production" and the full content root path.
  Those are host-side diagnostics on the operator's console - they are NOT
  in the response and never reach a caller. Recorded explicitly so a later
  reader does not mistake the log excerpt for endpoint output.

  FORWARD CONSTRAINT, written into the controller's own XML doc comment so
  it is read by whoever edits it next: if a later task needs a deeper
  readiness check - database reachable, migrations current, disk space -
  it belongs behind authorization on a separate endpoint. It must not be
  added to this payload.
