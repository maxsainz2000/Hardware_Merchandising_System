--- 6. ANNOTATION added after reading section 4: pre-existing 3306 rules ---

Section 4 surfaced inbound rules that do NOT belong to this project and were
not created by it. They belong to the unrelated "VISTA" / merchsys_central
installation already flagged as out-of-project at P0-04 and in manifest section 2:

    VISTA MariaDB LAN                 3306   Any profile   192.168.100.0/24
    MariaDB - Tailscale only (VISTA)  3306   Any profile   100.64.0.0/10
    MariaDB TCP 3306                  3306   Any profile   ANY REMOTE ADDRESS
    mysqld / mysqld.exe               Any    Public        ANY REMOTE ADDRESS

Read carelessly this looks like a hole. It is not, and the reason it is not is
worth stating precisely, because it converts an ambiguous test result into an
unambiguous one.

  A firewall rule ALLOWS traffic to reach a listener. It does not create one.
  MariaDB binds 127.0.0.1 (my.ini:46), so on this host there is no socket on
  any routable interface for those rules to admit traffic to.

The consequence for the P1-04 and P1-10 evidence is the opposite of a problem:

  A client's refused connection to 3306 CANNOT be attributed to the host
  firewall, because the host firewall explicitly permits 3306 from the entire
  192.168.100.0/24 subnet and, in one rule, from any address at all.

That removes the single largest confound in a remote negative test. Normally a
refusal cannot distinguish "nothing is listening" from "a firewall dropped it";
here the firewall is demonstrably NOT dropping it, so the only remaining
explanation is the bind address. The 8443 positive control in section 5 rules
out network-level isolation. Together the three facts leave exactly one cause.

ACTION SEPARATELY: these rules should still be reviewed and probably narrowed
or removed by whoever owns the VISTA installation. "MariaDB TCP 3306 / Any
remote address / any profile" is standing configuration that would expose that
project's database the moment its server binds a routable interface. That is
out of scope for this project's cards, but it is not out of scope for Max's
machine, and it is recorded here rather than silently passed over.
