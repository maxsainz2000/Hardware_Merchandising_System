===============================================================================
Done-when box 3 - a Cashier is refused (403); an Admin succeeds - asserted
in the P2-03 matrix
===============================================================================
Added as ProductsChangePrice_MatrixMatchesPolicyRegistry in
AuthorizationMatrixTests.vb, the same generic five-role-loop shape as
ConfigurationManage_MatrixMatchesPolicyRegistry: every one of the five spec
section 9 roles attempts PUT /api/v1/products/{id}/price against the real
HTTP pipeline; the product's price is reset to a known baseline before each
ALLOWED attempt so the request always represents a genuine change (never
collides with PriceChangeService's own NoChange outcome). Roles not in
Products.ChangePrice's AdminAndAbove list (ProcurementOfficer, InventoryClerk,
Cashier) must get 403 with a clean FORBIDDEN body (AssertCellAsync/
AssertCleanErrorBodyAsync - no stack trace, SQL, or credential fragment,
per ADR-014); SuperAdmin and Admin must get 2xx. An anonymous request must
get 401.

  Passed ProductsChangePrice_MatrixMatchesPolicyRegistry [1 s]
