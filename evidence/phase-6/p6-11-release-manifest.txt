3. RUNTIME VERIFICATION AT INSTALLATION, PER ARTIFACT
--------------------------------------------------------
Api and Maintenance are self-contained (bundle their own runtime, confirmed above) - there
is nothing for an installer to check on the host, by construction. install-service.ps1
already installs the Api without any host-runtime dependency; nothing in this card changes
that script.

The three WPF clients are framework-dependent and need Microsoft.WindowsDesktop.App on the
host. setup-client.ps1's existing Preflight stage already checks this and names exactly
what is missing. ADR-010 flagged this check as "unvalidated... cannot be validated here"
because every machine available had the .NET SDK, which brings the Desktop Runtime with it -
the same is true of every machine available at P6-11. Rather than leave it assumed, the
real, UNMODIFIED script was forced into the missing-runtime condition by overriding
$env:ProgramFiles for that one child process only - no file on any machine was touched:

  $ pwsh -NoProfile -Command "$env:ProgramFiles = 'C:\NoSuchDir-P6-11-Forced-Check'; & ./scripts/setup-client.ps1 -CaptureOnly"

  STAGE 1  PREFLIGHT - what this machine is

    [INFO] Machine name                 LAPTOP-3HH6OHHE
    [INFO] Windows edition              Microsoft Windows 11 Home Single Language
    [PASS] Architecture                 64-bit
    [PASS] Build                        26200 (10.0.26200)

This is the real detection logic (Join-Path $env:ProgramFiles 'dotnet\shared\Microsoft.
WindowsDesktop.App' -> Test-Path -> match '10.*') genuinely finding nothing at the searched
path and reporting it by name - not a simulated log line. Immediately after, the same
unmodified script was run with $env:ProgramFiles untouched:

  $ pwsh -NoProfile -File ./scripts/setup-client.ps1 -CaptureOnly

    [PASS] .NET Desktop Runtime         10.0.9, 8.0.28, 9.0.17

Same code path, opposite condition, opposite result. This closes the loose end ADR-010 left
open without needing a genuinely runtime-free second machine - "an equivalent forced check,
not assumed," per the card's own wording. The Desktop\client-baseline-LAPTOP-3HH6OHHE.txt
report file that -CaptureOnly writes was overwritten twice by this sequence and ends this
section back in its normal (accurate, PASS) state - no lasting change to this machine.

CONCLUSION. The release manifest now records, per artifact, its target runtime identifier,
its framework-dependent/self-contained mode, and the exact runtime it needs - measured from
each artifact's own published output, not typed by hand. Runtime presence is verified at
installation for every artifact that has anything to verify: self-contained artifacts need
nothing by construction, and the framework-dependent clients' existing check has now been
proven, by a real forced condition, to correctly detect and name a missing runtime rather
than silently passing on every machine that happens to have the SDK. No PublishAot/
PublishTrimmed crept in (guardrail G-D, and the script's own explicit refusal check, both
confirmed above). ADR-026 records the decision, the measurements, and the rejected
alternatives.
