5. What is NOT re-demonstrated here, and why that is not a gap
-------------------------------------------------------------------

The maintenance-mode HTTP round trip (POST .../enter, POST .../release) is
NOT re-run as a standalone manual session for this evidence file. It is
already proven end to end, through the real HTTP pipeline (not a mock, real
ASP.NET Core middleware pipeline, real MariaDB), by
MaintenanceModeTests.Restore_ThroughRealMaintenanceWorkflow_RecordsCompletedRestoreEvent
(P6-08), which is part of the full suite run in section 6 below and which
this document's own drift-check test
(BackupRestoreGuideDocumentationTests.MaintenanceModeJsonFields_MatchTheRealContractsClasses)
cross-checks the guide's JSON shapes and route names against. Standing up a
second, separate live dotnet run session against the same shared development
database purely to re-type the identical two curl calls would add risk (a
stuck maintenance lock on the live database if the manual session were
interrupted) for no additional evidentiary value over the automated test
that already exercises the exact same code path safely, with guaranteed
cleanup. This mirrors P6-08's own evidence file, section 6, which made the
same call for the same reason.
