6. A DEFECT FOUND AND FIXED DURING THIS CARD
---------------------------------------------------------------------

SaleRepository.SearchAsync's header reader called reader.GetString() on
the CorrelationId column (CHAR(36)). MySqlConnector maps CHAR(36) to
System.Guid, not String - the exact gotcha StockRepository.
ReadMovementItem and MaintenanceLockRepository's own headers already
name for every other CHAR(36) column in this schema, missed here because
this is the first time SaleRepository reads Sales.CorrelationId back
(every prior use only ever WROTE it). First surfaced as a live 500
INTERNAL_ERROR from GET /api/v1/sales during this card's own integration
test run - never shipped, since P6-02's own tests are what caught it.
Fixed by reading reader.GetGuid(5).ToString("d") instead, matching the
established pattern exactly. No error detail leaked to any client at any
point - ExceptionHandlingMiddleware's controlled 500 held throughout.

8. WHAT WAS NOT BUILT, AND WHY (scope discipline)
---------------------------------------------------------------------

Sales-by-product/by-cashier's "returned quantity"/"returns" columns are
computed correctly in ReportRepository's own SQL (LEFT JOIN against a
pre-aggregated SalesReturnLines/SalesReturns subquery, never a second
row-grain join that would fan out and double-count - see
ReportRepository.vb's own header) but are NOT independently reconciled
against a second, returns-side detail endpoint in this card's tests -
no GET exists yet for SalesReturns, and building the "Returns and
cancellations" report surface is P6-03's own card. This card's
reconciliation tests instead reconcile the SALES-side figures (gross
value, quantity sold, per-cashier/per-payment-method totals) against
GET /api/v1/sales, which is what ADR-023's two named risk classes (the
day-boundary conversion and the captured-cost join) actually exercise -
the returns-netting arithmetic is ordinary, already-precedented SQL
(the identical LEFT-JOIN-a-pre-aggregated-subquery shape P5-11 already
uses for SalesReturnLines), not one of the two defect classes this
phase's reconciliation harness exists to catch.
