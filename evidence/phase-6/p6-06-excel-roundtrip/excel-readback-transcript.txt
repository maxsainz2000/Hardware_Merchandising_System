-------------------------------------------------------------------
3. What this proves
-------------------------------------------------------------------

- FORMULA-INJECTION MITIGATION HOLDS ON REAL, LIVE DATA. The stored value
  began with '=', which unmitigated (see CsvExporter.vb's own header and
  the synthetic probe below) Excel evaluates as a formula
  (HasFormula = True, "=1+1" -> 2). Here HasFormula = False: the exported
  field was "'=1+1, ""special"" café" (apostrophe-prefixed, RFC4180-quoted
  because of the embedded comma) - CsvExporter.EscapeField's exact
  mitigation, exercised through the full production pipeline
  (ReportService -> ReportCsvFormatters -> CsvExporter -> HTTP response),
  not called directly. The apostrophe is visible in Excel's own Text/Value2
  - the documented trade-off, not a defect.

- THE EMBEDDED COMMA AND DOUBLE QUOTE SURVIVED INTACT. Excel's Text shows
  `"special"` with the RFC4180 double-quote escaping correctly unwound by
  Excel's own CSV parser, and the comma did not split the field into two
  columns (categoryId column is still empty on this row, not "special" or
  "1+1").

- THE NON-ASCII CHARACTER (é) DISPLAYED CORRECTLY, confirming the UTF-8 BOM
  this class always writes (ADR-024) round-trips through a real HTTP
  response body and a real Excel file-open with no mangling, on a
  697KB/7781-row real export - not just the small synthetic sample used to
  make the original BOM decision.

-------------------------------------------------------------------
4. Cross-reference to the synthetic probe behind the ADR-024 decision
-------------------------------------------------------------------

Before any of CsvExporter.vb was written, the same COM-automation technique
was used on small synthetic files to decide the formula-injection mitigation
and the BOM question in the first place (docs/adr.md ADR-024 records both
decisions and the measurements behind them):

  =1+1   unmitigated -> HasFormula=True,  Value2=2   (executes)
  +1+1   unmitigated -> HasFormula=True,  Value2=2   (executes)
  -1+1   unmitigated -> HasFormula=True,  Value2=0   (executes)
  @SUM(1+1) unmitigated -> HasFormula=False (did not execute on this build,
                            mitigated anyway per the card's own four-character list)
  '=1+1, '+1+1, '-1+1, '@SUM(1+1) (apostrophe-prefixed) -> HasFormula=False
                            for all four, Text keeps the leading apostrophe

  UTF-8 BOM vs BOM-less, identical accented-name row -> both opened
  correctly on this machine's Excel build (16.0.20426.20000); BOM kept
  anyway as the zero-cost, standard defensive default for a build this
  project cannot assume the classroom machine matches.

This transcript (section 2 above) is the SAME measurement repeated against
the real production pipeline's own live output, not the synthetic probe
again.
