Imports Microsoft.Extensions.DependencyInjection
Imports Microsoft.Extensions.Hosting

Public Module Program

    Public Sub Main(args As String())

        Dim builder = WebApplication.CreateBuilder(args)

        builder.Services.AddControllers()

        Dim app = builder.Build()

        app.MapControllers()

        app.Run()

    End Sub

7  FRICTION AUDIT - DOES P1-02a NEED TO RUN?
---------------------------------------------------------------------------

P1-02a runs ONLY if rung A showed friction: "an SDK target that needed a
workaround, a build warning you had to suppress, a property you had to set
that is not in the standard template."  Taken one at a time:

  a) An SDK target that needed a workaround     : NONE. No target was
     overridden, no Import was added, no MSBuild property was set to route
     around a C#-assuming target. The Web SDK handled a .vbproj unmodified.

  b) A build warning that had to be suppressed  : NONE. The build emitted
     0 warnings and the project file contains no NoWarn.

  c) A property set beyond the standard template: TESTED DIRECTLY, and the
     answer is no. The obvious candidate was
     <EnableRequestDelegateGenerator>false</EnableRequestDelegateGenerator>,
     which CLAUDE.md section 3 mandates. To find out whether it is a
     WORKAROUND or a PRECAUTION, it was removed and the project rebuilt from
     scratch:

       $ dotnet build -v minimal --no-incremental   (property removed)
         Build succeeded.
             0 Warning(s)
             0 Error(s)
         EXIT CODE: 0

     It builds fine without it. The Request Delegate Generator only applies
     to MINIMAL API endpoints, and this project uses CONTROLLERS - which is
     already the mandated design for independent reasons. So the property is
     defence in depth, not a workaround for a failure. KEEP IT SET (it costs
     nothing and protects anyone who later reaches for a minimal-API lambda),
     but it does NOT count as friction.

     The remaining properties - OutputType, TargetFramework, RootNamespace,
     AssemblyName, OptionStrict/Explicit/Compare/Infer, PublishAot/Trimmed
     false - are ordinary project settings or this repo own conventions from
     Directory.Build.props. None is a workaround.

  d) BONUS CHECK - did the Web SDK generate any C# behind our backs?

       $ Get-ChildItem -Recurse -Include *.cs,*.csproj
         count: 0

     Intermediate files generated into obj/ by extension:
       16 .cache   13 .json   6 .dll   4 .txt   4 .vb   2 .editorconfig
        2 .exe      2 .pdb    1 .props 1 .targets 1 .Up2Date

     FOUR .vb files, ZERO .cs files. The SDK generates its AssemblyInfo and
     related intermediates in Visual Basic for a VB project. Guardrail G-A
     will not fight the build, and the language rule holds all the way down
     to generated code. This was a genuine open risk and it is now closed.

  CONCLUSION: zero friction on all four counts.
  => P1-02a SHOULD BE SKIPPED when Phase 1 reaches it. Proving a fallback
     there is no reason to need is busywork, and the card says so itself.
     If P1-02 in-repo behaves differently from this probe, that difference
     is itself the friction and P1-02a triggers on it.
