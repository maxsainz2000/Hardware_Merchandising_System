  Occupied addresses observed: .1 (gateway), .6, .74, .83, .149, .174, .175,
  .187, .191. They span BOTH SIDES of the host address .165, and reach as
  high as .191.

  A DHCP server that has already issued .191 is handing out addresses from a
  pool that almost certainly INCLUDES .165. The default pool on Huawei home
  gateways is typically 192.168.100.2 - 192.168.100.254. If that is the case
  here, the static address configured on this host sits inside the pool, the
  router does not know it is taken, and it can lease .165 to a phone that
  joins the Wi-Fi. The most likely moment for that to happen is when the room
  fills with people - i.e. during the demo.

  The MAC addresses are locally-administered (first octet has bit 1 set:
  BA, 12, 7A, 42, E6, 6E, 4A, FE) - these are randomised-MAC mobile devices
  joining and leaving. Exactly the population that churns through a DHCP pool.

  This CANNOT be resolved from the host. Reading or changing the pool needs
  the router admin UI. Confirmed reachable:

    http port 443   on 192.168.100.1 : open=False
    http port 8080  on 192.168.100.1 : open=False

    => router admin UI at  http://192.168.100.1   (port 80 open, 443/8080 closed)
