SECTION 9  CRLF SHEBANG HARDENING - PROVEN AGAINST A SIMULATED FUTURE CLONE
===========================================================================

Added at P0-07. .gitattributes marks *.ps1 as eol=crlf, so on the NEXT clean
clone scripts/install-hooks.ps1 will be checked out with CRLF endings - and
it embeds the pre-commit hook body as a here-string. A naive writer would
then emit "#!/bin/sh<CR><LF>", sh would look for an interpreter named
"/bin/sh\r", and THE GIT HOOK WOULD SILENTLY STOP RUNNING. That is the exact
failure .gitattributes was created to prevent, reintroduced by the fix for it.

install-hooks.ps1 now normalises the body to LF, writes bytes with
WriteAllText, and asserts on the result - refusing to install a hook whose
shebang ends CRLF.

Tested by simulating the future state rather than waiting for it: the script
was converted to fully CRLF and executed against the real repository.
