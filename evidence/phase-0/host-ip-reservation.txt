SECTION 2 - Reverted to DHCP 2026-08-17 (CURRENT STATE)
===========================================================================

=== Why it was reverted ===
A Windows static IPv4 address is a property of the ADAPTER, not of a Wi-Fi
profile. The manual 192.168.100.165/24 therefore followed the laptop onto
every network it joined. At the DILG-Aparri OJT office the machine associated
with the office Wi-Fi but reported "connected, no internet" and could not
route or resolve.

=== Notable finding: the office network shares the home subnet ===
The office Wi-Fi (profile "LNB") uses 192.168.100.0/24 with gateway
192.168.100.1 - IDENTICAL to the home Huawei network. The failure was
therefore NOT a subnet mismatch. The two plausible causes are:

  (a) another device on the office LAN already held .165, or
  (b) more likely on managed government-office equipment: DHCP snooping /
      IP source guard dropping traffic from an address the network never
      leased.

Either way the operational conclusion is the same and it is important for
deployment: A MANUAL STATIC ADDRESS MAY BE SILENTLY BLOCKED ON THE
DEPLOYMENT NETWORK. A router-side MAC DHCP reservation is the only method
that can be relied on. This supersedes the P0-05 approach in SECTION 1.

Secondary consequence: two distinct networks sharing one subnet makes any
Tailscale subnet routing between them ambiguous, and makes "which
192.168.100.x network am I on?" a real question during testing. Confirm by
network profile name (NetProfile.Name), never by address alone.

=== Commands run (elevated PowerShell 7.6.5) ===
$idx = (Get-NetAdapter -Name "Wi-Fi").ifIndex
Set-NetIPInterface       -InterfaceIndex $idx -Dhcp Enabled
Remove-NetIPAddress      -InterfaceIndex $idx -AddressFamily IPv4 -Confirm:$false -ErrorAction SilentlyContinue
Remove-NetRoute          -InterfaceIndex $idx -AddressFamily IPv4 -Confirm:$false -ErrorAction SilentlyContinue
Set-DnsClientServerAddress -InterfaceIndex $idx -ResetServerAddresses
ipconfig /renew
ipconfig /flushdns

SECTION 3 - Back on the home network 2026-08-18 (CURRENT STATE)

=== The trap: DHCP handed back the SAME address as the old static ===
On rejoining 'HUAWEI-5G-fP2f 2' the host was leased 192.168.100.165/24 -
byte for byte the address that SECTION 1 configured statically and
SECTION 2 removed. The router evidently still associates that address with
this adapter's MAC.

This is more dangerous than an obviously wrong address, because it makes
the stale hardcoded value in docs/installation-guide.md section 1.1 pass a
test today and fail later. It is a LEASE, not a reservation:

Get-NetIPAddress -InterfaceIndex 14 -AddressFamily IPv4
  IPAddress     : 192.168.100.165
  PrefixLength  : 24
  PrefixOrigin  : Dhcp          <-- NOT Manual. The revert held.
  SuffixOrigin  : Dhcp
  AddressState  : Preferred
  ValidLifetime : 22:40:25      <-- ~24h lease, no renewal guarantee

(Get-NetIPInterface -InterfaceIndex 14 -AddressFamily IPv4).Dhcp : Enabled
DNS server                                                       : 192.168.100.1

=== Operational conclusion ===
Do NOT read "the host is on .165" as "the host address is settled". Nothing
may depend on .165 until a router-side MAC reservation makes it durable.
P0-05 remains open on exactly that step.
