=== P5-07: The atomic sale - seven effects, one transaction ===
Captured 2026-08-30, against the real pinned MariaDB instance (ADR-002:

--- What was built ---
POST /api/v1/sales (Sales.Create, CashierAndAbove - live for the first time).
One transaction commits: the Sales header, its SaleLines, the one SalePayments
record, one StockMovements row per line, the conditional StockBalances
decrement, and the AuditLogs row - or none of them (spec section 11). Session
totals are satisfied structurally (Sales.CashierSessionId written in the same
transaction; CashierSessionRepository.GetPaymentTotalsAsync, P5-04, computes
them on demand from committed rows) - no stored running counter to drift.

Design calls made and why (full reasoning is in each file's own header):
  - No client-supplied price. Each line is only {ProductId, Quantity}; the
    server reads Products.Price/Cost fresh, inside the transaction, via
    ProductRepository.GetByIdAsync's existing transaction overload - a plain
    read, not FOR UPDATE, so two concurrent sales naming the same two
    products in reverse order cannot deadlock against each other.
  - No client-supplied CashierSessionId. The server locks and finds the
    CALLING user's own Open session (new CashierSessionRepository.
    GetOpenForUpdateByUserAsync) and refuses 409 CASHIER_SESSION_REQUIRED
    if none exists.
  - One Payment per sale, not a list - spec section 10.3's "record an
    allowed payment" (singular); SalePayments stays one-to-many in the
    schema for a future card. Amount always equals the sale Total.
  - SalePaymentResponse.Status is always the literal "Recorded" (G-24) -
    asserted directly against the real JSON body, not just the enum.
  New files: Contracts/Sales/{CreateSaleRequest,CreateSaleLineRequest,
  CreateSalePaymentRequest,SaleResponse,SaleLineResponse,SalePaymentResponse}.vb;
  Infrastructure/Data/SaleRepository.vb (new) + CashierSessionRepository.vb
  (+GetOpenForUpdateByUserAsync); Api/Sales/{SaleOutcome,SaleService}.vb;
  Api/Controllers/SalesController.vb; Program.vb (DI registration);
  tests/SaleServiceTests.vb (new, 14 tests); AuthorizationMatrixTests.vb
  (+SalesCreate_MatrixMatchesPolicyRegistry).
