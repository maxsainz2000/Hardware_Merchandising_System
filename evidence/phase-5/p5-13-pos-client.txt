===============================================================================
0. What this card built
===============================================================================

Merchandising.POS now has a real, three-tab window (Session / Checkout /
Returns), following the exact shape Merchandising.Procurement's MainWindow
(P3-07) and Merchandising.Inventory's MainWindow (P4-12) already establish:
one MerchandisingApiClient, a sign-in panel, RelayCommand/AsyncRelayCommand
bindings, ApiFailurePresenter surfacing every server refusal verbatim, and an
explicit, globally-unique, ascending-per-screen TabIndex on every interactive
control.

New ClientCommon surface (none of this existed before this card):
  MerchandisingApiClient.OpenCashierSessionAsync    POST /api/v1/cashier-sessions
  MerchandisingApiClient.CloseCashierSessionAsync   POST /api/v1/cashier-sessions/{id}/close
  MerchandisingApiClient.CreateSaleAsync            POST /api/v1/sales
  MerchandisingApiClient.RecordSalesReturnAsync     POST /api/v1/sales/{saleId}/returns

New POS view models: SessionViewModel, CheckoutViewModel, ReturnsViewModel,
SaleCartLineViewModel, and a MainViewModel composition root wiring them
together with one shared ObservableCollection(Of SaleResponse) that Checkout
appends to and Returns reads from (there is no GET /api/v1/sales or GET
/api/v1/sales/{id} route anywhere in this API - a return can only be recorded
against a sale this client itself completed this run; see CheckoutViewModel's
and ReturnsViewModel's own file headers for the full reasoning).

The nine named operations, and where each lives:
  1. Sign in            MainViewModel.SignInAsync            (Sign-in panel)
  2. Open a session      SessionViewModel.OpenAsync           (Session tab)
  3. Look up a product   CheckoutViewModel.SearchProductsAsync (Checkout tab)
  4. Build a cart        CheckoutViewModel.AddToCart/RemoveFromCart
  5. Take a payment      CheckoutViewModel (Cash/Card/EWallet selector)
  6. Complete the sale   CheckoutViewModel.CompleteSaleAsync
  7. Show receipt data   CheckoutViewModel.ReceiptSummary + LastSale.Lines grid
  8. Take a return        ReturnsViewModel.RecordReturnAsync   (Returns tab)
  9. Close the session   SessionViewModel.CloseAsync

3. THE BLOCKER - redeploying needs elevation this session does not have
===============================================================================

  pwsh ./scripts/publish-release.ps1 -Component Api -Mode SelfContained -OutputRoot C:\MerchandisingService

failed partway with "Access to the path '...\clrjit.dll' is denied" - the
RUNNING service still holds that file open, so a self-contained publish
cannot overwrite it in place. The service must be stopped first, which - like
install-service.ps1 itself - requires an elevated shell:

  [Security.Principal.WindowsPrincipal]...IsInRole(...Administrator) -> False

Per this session's own service-redeploy-acl-trap note, this session has none.
NOTHING WAS LEFT BROKEN: the service was re-checked after the failed publish
and is still Running and healthy (GET /health -> 200); publish-release.ps1's
own delete-before-publish step never reached the target directory, and the
partial attempt touched no file the running process needed. Per CLAUDE.md
section 7, an elevation gap is a stop condition to report, not a reason to
retry with a workaround (e.g. --no-verify-equivalent flags do not exist here,
and none were sought).

REMEDY - to be run by the operator, in an ELEVATED PowerShell 7 session, from
the repository root:

  Stop-Service MerchandisingApi -Force
  pwsh ./scripts/publish-release.ps1 -Component Api -Mode SelfContained -OutputRoot C:\MerchandisingService
  pwsh ./scripts/install-service.ps1 -PublishDir C:\MerchandisingService\Api-sc

install-service.ps1 deletes and recreates the service rather than
re-registering over a live one, re-grants the NT SERVICE\MerchandisingApi
virtual account read access to the config and the .pfx, and refuses to report
success until something is actually listening on 8443 (install-service.ps1's
own header, and P4-15's own transcript of that same sequence).
